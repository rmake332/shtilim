# דיבוג מפתח מחשבון אופק חדש (שתילים)

מחשבון אופק חדש (טבלת `מחשבון אופק חדש`, `tbluSqfzeX9Ns452y`) הוא טבלת חיפוש:
כל שורה מזוהה ע"י מפתח `סיכום` (`fldbLwWMO4KFfo7KY`). `lookupOfek` מחפש התאמה
מדויקת; אם אין שורה — התקן נחסם. רוב באגי "not found" הם מפתח שגוי, לא דאטה חסר.

## מבנה המפתח (buildOfekKey ב-ofek.ts)

```
{שכבה}{שעות_גיל}{כן|לא}{קטגוריה}{סך_שעות}      דוגמה: "חטיבה0כןהוראה5"
```
- **שכבה**: גנים / יסודי / חטיבה
- **שעות_גיל**: מספר (בד"כ 0)
- **משרת אם**: `כן`/`לא`
- **קטגוריה**: `פרא` / `הוראה` / `הוראה_ללא_שהייה` — **נגזרת מ-`scheduleType`**
  דרך `ofekCategoryFor`, לא מהשדה `category`! זו הטעות הכי נפוצה.
- **סך_שעות**: השעות הסופיות אחרי עיגול לחצי (`roundToHalf`).

## הכלי

```bash
# בנייה מרכיבים
node .claude/skills/ofek-key-debug/scripts/ofek-key.mjs \
  --layer יסודי --age 0 --mother לא --category הוראה --hours 30

# נתינת scheduleType במקום category (הסקריפט גוזר את קטגוריית האופק)
node .claude/skills/ofek-key-debug/scripts/ofek-key.mjs \
  --layer גנים --age 0 --mother כן --schedule-type "הוראה ללא שהייה" --hours 22

# חיפוש מפתח מוכן (למשל מתוך debug.ofekKey בתשובת compute)
node .claude/skills/ofek-key-debug/scripts/ofek-key.mjs --key "חטיבה0כןהוראה5"
```

מה הוא עושה: בונה את המפתח, מחפש בטבלה, ומדפיס את שורת המחשבון אם נמצאה. אם לא —
**מנסה אוטומטית את המפתח עם משרת-אם ההפוכה** ומדווח אם דווקא הוא קיים (המלכודת
שבה עובדת עם כמה תקנים קטנים חוצה 79% רק ביחד, כך שמשרת-אם מתהפכת). קורא טוקן
מ-`.env.local`; בסשן בלי טוקן — השתמש בכלי MCP של Airtable על טבלת `tbluSqfzeX9Ns452y`.

## סדר הבדיקה כשמתקבל not_found

1. **קטגוריית האופק** — האם היא נגזרת מ-`scheduleType` הנכון? (`פרא`≠`הוראה`≠`הוראה_ללא_שהייה`).
   ראה `ofekCategoryFor` ב-`src/lib/schedule/ofek.ts`.
2. **סך השעות** — עוגל לחצי? בפרא השעות במפתח הן פרונטלי+פרטני בלבד (השהייה נוספת מעל).
3. **משרת אם** — הרץ את הכלי; אם המפתח ההפוך קיים, הבעיה היא בקביעת משרת-אם
   (שדה ילדים<14 / היקף משרה כולל של יתר התקנים). ראה `resolveByOfekOutput`
   ב-`src/app/api/schedule/compute/route.ts`.
4. **`ofek_combined_not_found`** — הכשל הוא על **סכום כל תקני העובד**, לא על התקן
   הבודד. בנה את המפתח המשולב (סך השעות של כל התקנים יחד) ובדוק אותו.

לאימות שהתיקון נכון מקצה-לקצה, השתמש בסקיל `verify-schedule`.
